# P-13 receipt — production text and math pipeline

Closed: 2026-07-30

## Decision

- ordinary text: Rustybuzz shaping over bundled Noto Sans OpenType data
- glyph rendering: cached TrueType outlines tessellated as vectors in Rust
- math: sandboxed Tectonic compilation on the local server
- conversion: PDF to normalized SVG paths, cached by source hash
- browser rendering: usvg normalization, lyon tessellation, 4× MSAA, WebGPU

This replaces the prototype bitmap font. Text and math stay vector at every
renderer boundary.

## Fidelity evidence

- proportional metrics and `AV` kerning tests pass
- multiline centering and cached real glyph-outline tests pass
- a live integral/fraction/radical scene rendered correctly with no browser errors
- SVG solid fills, opacities, strokes, caps, joins, and fill rules are retained
- MathTex is compiled by a real TeX engine, not interpreted by the model or replaced
  with Unicode approximations

## Morphability result (superseded 2026-08-12)

Glyph outlines are morphable paths, but the current `MathTex` node is one SVG object
without semantic subexpression IDs. It cannot yet implement Manim's
`TransformMatchingTex` correspondence. Required follow-up:

1. tag TeX tokens/subexpressions before compilation,
2. retain token-to-path groups through SVG normalization,
3. normalize contour direction and start points,
4. match exact tokens first and use geometric assignment only as fallback.

The regular-Manim compatibility compiler now retains the original
`TransformMatchingTex` token groups, repeated-key membership, explicit
`key_map`, mismatch mode, source/target node sets, and timing. Straight paths
lower to two retained native affine or path-data endpoint keyframes using Manim's exact logistic smooth;
nonlinear/custom paths stay exact via sampled tracks and emit a bounded fallback
reason. See `benchmarks/compat/transform-matching-semantic-receipt.json`.
