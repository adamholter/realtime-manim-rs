# P-10 renderer shootout receipt

Status: native Metal and Vello/WebGPU prototype evidence complete; D-20 remains open.

## Scope

`tools/renderer-shootout` renders equivalent retained vector workloads through:

- Vello 0.9 with its compute-based area antialiaser and pinned wgpu 29 stack;
- realtime-manim's current lyon tessellation plus one retained wgpu 30 vertex/index stream with 4× MSAA.

This is experimental architecture evidence, not an architecture freeze. Both paths render to 1280×720 offscreen textures, wait for GPU completion for every measured frame, and read back the final image. The suite covers 1,248 independent filled primitives, 420 multi-cubic strokes, 5,500 independent vector-field strokes, 900 ordered translucent paths, and 456 compound cubic outlines.

## Native Metal result

Command:

```bash
cargo run --release -p realtime-manim-renderer-shootout -- \
  --output benchmarks/renderer-shootout/2026-08-12-metal \
  --width 1280 --height 720 --warmup 12 --iterations 60 \
  --background-load interactive-apps-open
```

Environment: macOS on Apple M4, 1280×720 offscreen, normal interactive application load. Every workload uses 12 warmup frames and 60 measured frames.

| Workload | Vello p95 | lyon/wgpu p95 | Vello retained bytes | lyon/wgpu retained bytes | RGB RMSE |
| --- | ---: | ---: | ---: | ---: | ---: |
| primitive grid | 1.662 ms | 0.351 ms | 126,082 | 1,136,304 | 0.0258 |
| Bézier strokes | 1.905 ms | 0.570 ms | 39,085 | 2,707,848 | 0.0377 |
| dense vector field | 1.685 ms | 0.335 ms | 236,534 | 660,000 | 0.0256 |
| translucent layers | 1.801 ms | 0.576 ms | 105,334 | 1,503,936 | 0.0026 |
| outline glyphs | 2.138 ms | 0.528 ms | 57,034 | 1,149,696 | 0.0187 |

The retained-byte figures count Vello's encoded streams and lyon's tessellated vertex/index payload. They do not claim total process or GPU memory. The image RMSE is diagnostic rather than a pass/fail threshold because the backends use different antialiasing algorithms; all ten rendered PNGs were visually inspected, and the compound outline fill-rule mismatch found by that inspection was fixed before the final run.

## Browser WebGPU comparison

Commands:

```bash
cargo build --release -p realtime-manim-renderer-shootout --lib \
  --target wasm32-unknown-unknown --no-default-features --features browser-vello
wasm-bindgen target/wasm32-unknown-unknown/release/realtime_manim_renderer_shootout.wasm \
  --target web --out-dir tools/renderer-shootout/web/pkg --out-name vello_shootout
cargo build --release -p realtime-manim-renderer-shootout --lib \
  --target wasm32-unknown-unknown --no-default-features --features browser-lyon
wasm-bindgen target/wasm32-unknown-unknown/release/realtime_manim_renderer_shootout.wasm \
  --target web --out-dir tools/renderer-shootout/web/pkg --out-name lyon_shootout
python3 -m http.server 8932 --bind 127.0.0.1 \
  --directory tools/renderer-shootout/web
npm run test:renderer-shootout-browser
```

Isolated headless Chrome acquired WebGPU adapters for both backends and rendered/read back the same 1,248-primitive workload for 40 measured frames each. Console/page errors: zero.

| Browser backend | p50 | p95 | p99 | mean | content pixels | checksum | retained bytes |
| --- | ---: | ---: | ---: | ---: | ---: | --- | ---: |
| Vello 0.9 / wgpu 29 | 0.900 ms | 1.100 ms | 1.100 ms | 0.915 ms | 230,597 | `11185c9be9c03358` | 126,082 encoded |
| lyon / wgpu 30 | 0.400 ms | 0.700 ms | 0.900 ms | 0.398 ms | 213,872 | `f83315d124539993` | 1,136,304 tessellated |

The unoptimized generated Wasm payloads were 1.5 MiB for Vello and 340 KiB for lyon/wgpu. This run favors lyon at p50, p95, p99, and mean. The two backends rendered the same retained paths; their content-pixel counts differ by 7.8% because Vello area AA and lyon 4× MSAA cover edge pixels differently. The automated spatial proof also requires matching two-pixel-tolerance content bounds and a normalized error below 20% across a 64×36 occupancy grid; this run produced identical `[8,2,1272,717]` bounds and 7.25% occupancy error.

This browser comparison establishes feasibility and nonblank GPU results for both stacks. It does not yet cover Safari/Firefox, run multiple browser trials, include the other four native workloads, or exercise Vello's full Manim feature surface.

## Recommendation

Keep lyon + wgpu as the current experimental baseline: it won all five native p95 workloads and the browser comparison, and already owns the broader realtime-manim feature surface. Preserve the renderer boundary and do not freeze D-20 yet. Vello's much smaller retained vector representation and successful browser WebGPU proof justify keeping the prototype available for future geometry-heavy scenes, but this run provides no performance reason to replace the production path.

Remaining D-20 evidence: repeated full-suite browser trials, Safari/Firefox capability matrix, full-feature corpus correctness rather than solid-vector workloads alone, startup/binary-size accounting after optimization, and stress measurements under representative application load.
